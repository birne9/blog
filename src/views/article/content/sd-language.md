## 编译与解释

翻译程序有两种形态。**编译器**(Compiler)把源程序**整体翻译成目标程序**(通常是机器码),之后目标程序独立运行,翻译只发生一次;**解释器**(Interpreter)**不产生目标程序**,**边翻译边执行**,每次运行都要重新翻译。编译型语言(C、C++)运行快、可移植性差,解释型语言(早期 BASIC)恰好相反。

Java 是**编译加解释的混合模式**:javac 先把 .java 源文件编译成 **.class 字节码**,字节码与平台无关;运行时由 **JVM**(Java Virtual Machine)解释执行字节码,热点代码再由 **JIT**(Just In Time)编译器就地编译成机器码缓存起来,越跑越快。

两种方式的优缺点对照:**编译方式执行效率高**、便于做全局优化,但目标程序依赖具体平台;**解释方式跨平台**、逐条执行报错定位直观,但运行速度慢。常见语言归属要记准:**C 是纯编译,早期 BASIC 是纯解释,Java 和 Python 都是先编译成字节码再解释执行**。

类比前端:这条链路和前端几乎一模一样——TypeScript 先编译成 JavaScript(编译),V8 执行 JS 时先解释、热点函数再 JIT 成机器码(解释加 JIT)。Java 的 .class 对应 TS 的编译产物,JVM 对应 V8,"一次编写到处运行"对应"一个页面处处打开"。理解了 TS 到 JS 再到机器码的三段式,就理解了 Java 的运行模型。

> 考点提示:常问编译方式和解释方式的根本区别——**编译产生目标程序、解释不产生目标程序**,这是分水岭。问 Java 属于哪种,标准表述是**先编译成字节码、再由虚拟机解释执行的混合型**,只答编译或只答解释都不完整。

## 编译过程的六个阶段

编译器内部分六个阶段,**符号表管理和出错处理贯穿始终**。1. **词法分析**:从左到右扫描字符流,切成一个个单词(token),识别出标识符、常数、运算符、界符。2. **语法分析**:按语法规则把单词串组织成**语法树**,检查结构是否合法。3. **语义分析**:检查意义是否正确,主要是**类型检查**与类型转换,例如运算对象类型是否匹配、变量是否先声明后使用。4. **中间代码生成**:转成与机器无关的中间形式,常见**三地址码、四元式、逆波兰式**。5. **代码优化**:做等价变换让代码更快更省,如删除公共子表达式、常量合并。6. **目标代码生成**:产出汇编或机器码,并完成寄存器分配。

以赋值语句 x = (a + b) * 2 为例走完全程:

```text
词法分析输出单词流:
标识符 x | 赋值号 = | 左括号 ( | 标识符 a | 加号 + | 标识符 b | 右括号 ) | 乘号 * | 常数 2

语法分析生成语法树:
      =
     / \
    x   *
       / \
      +   2
     / \
    a   b

语义分析: 检查 a、b、x 均已声明且类型相容, 常数 2 与表达式类型匹配

中间代码 (三地址码):
t1 = a + b
t2 = t1 * 2
x  = t2

代码优化: 常量 2 可参与常量合并; 若 (a+b) 前面算过可直接复用

目标代码:
LOAD  a
ADD   b
MUL   2
STORE x
```

> 考点提示:高频考法是给一段错误代码问属于哪个阶段——**变量未声明、类型不匹配是语义错误**,**括号不匹配、缺少分号是语法错误**,**出现非法字符是词法错误**。还有一类问哪个阶段与机器有关:**只有目标代码生成与具体机器强相关**,**中间代码刻意保持与机器无关**。

类比前端:词法分析 ≈ 分词器把源码切成 token,语法分析 ≈ 生成 AST(Abstract Syntax Tree),语义分析 ≈ 类型检查,中间代码 ≈ Babel 降级后的中间产物,目标代码 ≈ 最终 bundle。写过 Babel 插件或用 AST 做过代码改写的话,整个编译前端就是你天天打交道的流程。

再补两个概念:词法分析、语法分析、语义分析和中间代码生成合称**编译前端**,与源语言关系密切;代码优化中的一部分和目标代码生成合称**编译后端**,与目标机器关系密切。**符号表贯穿编译全程**,记录每个标识符的类型、作用域、存储地址等信息,语义分析和代码生成都要查它。

## 文法基础

形式文法 G 是一个**四元组**:**G = (VT, VN, S, P)**。**终结符 VT** 是语言的基本符号(如 id、+、具体字符),是句子中最终出现的符号;**非终结符 VN** 是语法变量(如 E 表示表达式、T 表示项),可以被继续替换;**开始符 S** 是推导的起点;**产生式 P** 是形如 A → α 的替换规则。

推导与归约:从开始符出发,反复用产生式右部替换左部,叫**推导**;反过来把符号串逐步收缩回开始符,叫**归约**。推导过程中得到的任意符号串叫**句型**;**只含终结符的句型叫句子**;一个文法能推出的所有句子的集合,叫这个文法的语言 **L(G)**。

```text
文法 G: E → E + T | T
       T → T * F | F
       F → ( E ) | id

推导句子 id + id * id (最左推导, 每步替换最左边的非终结符):
E ⇒ E + T
  ⇒ T + T
  ⇒ F + T
  ⇒ id + T
  ⇒ id + T * F
  ⇒ id + F * F
  ⇒ id + id * F
  ⇒ id + id * id
```

语法树(分析树)是推导的图形表示,上例推导对应的语法树如下:

```text
        E
      / | \
     E  +  T
     |    /|\
     T   T * F
     |   |   |
     F   F   id
     |   |
     id  id
```

读法:根节点是开始符 E,每个内部节点对应一次产生式替换,所有叶子从左到右拼起来就是句型 id + id * id。树里最左边那棵只有一层的子树叫**句柄**,自下而上归约时每次先归约的就是它。

若某个文法存在一个句子对应**两棵不同的语法树**,这个文法就是**二义文法**。判断某符号串是不是某文法的句子用推导,判断是不是句型看它能否从开始符推出——**句型可以含非终结符,句子必须只含终结符**,这组术语辨析经常在选择题里挖坑。

## 正规式与有限自动机

正规式(正则表达式)用三个运算符描述字符串集合:**连接**(常省略不写)、**或**(竖线)、**闭包**(星号,表示重复零次或多次)。优先级:**闭包最高,连接次之,或最低**。

```text
正规式 (a|b)*abb 表示: 以 abb 结尾的任意 a/b 串
属于该语言: abb、aabb、babb、abababb
不属于:     ab、aba、bba、abba
```

再练一道,判断正规式 a*b* 都能生成哪些串:

```text
a*b* 表示: 任意个 a (可以是零个) 后面接任意个 b (可以是零个)
属于:   空串、a、aaab、b、ab
不属于: aba  (b 出现之后不能再出现 a)
```

有限自动机是识别正规式的机器模型。**NFA**(Nondeterministic Finite Automaton)非确定有限自动机,**同一状态读同一字符可以转移到多个状态**;**DFA**(Deterministic Finite Automaton)确定有限自动机,**每个状态读每个字符至多转移一次**。**二者表达能力等价**,**NFA 可以转化为 DFA**。

考题做法:给出自动机图和候选串,从初态出发按字符逐个转移,串走完后**停在终态(图中画双圈)则被接受**;NFA 只要**存在一条到达终态的路径**就算接受。

```text
例题: DFA 的初态为 S, 终态为 C, 状态转移如下
S -a→ A    S -b→ S
A -a→ A    A -b→ B
B -a→ A    B -b→ C
C -a→ A    C -b→ S

判断串 aba: S -a→ A -b→ B -a→ A, 停在 A, 非终态, 不接受
判断串 abb: S -a→ A -b→ B -b→ C, 停在终态 C, 接受
判断串 bab: S -b→ S -a→ A -b→ B, 停在 B, 非终态, 不接受
结论: 该自动机识别以 abb 结尾的串, 与正规式 (a|b)*abb 等价
```

NFA 的判断稍有不同:它允许一个状态读同一字符走向多个分支,甚至允许不读字符的空跳。判断时把所有可能路径都走一遍,只要**存在一条能到达终态的路径**就算接受。NFA 看着灵活,表达能力和 DFA 却完全一样,任何 NFA 都能用**子集构造法**转成等价的 DFA,这个结论本身也常考。

> 考点提示:判断自动机接受哪个串,**把四个选项逐个跑一遍**最稳妥,注意看清初态、终态和自环。正规式与自动机的对应题,先抓**必须出现的子串结构**(如此例的 abb 后缀),用它排除选项最快。

## 语法分析:自上而下与自下而上

语法分析有两大流派。**自上而下**:从开始符出发为输入串建立推导,试图推出输入串,代表方法有**递归下降分析和 LL(1) 分析**;它对文法有要求,必须**消除左递归**(形如 E → E + T 的产生式会让递归下降陷入死循环),还要提取左公共因子。**自下而上**:从输入串出发逐步归约到开始符,代表是**移进-归约分析和 LR 系列**(LR(0)、SLR、LR(1)、LALR),核心是维护一个**分析栈**,逐个读入符号压栈(移进),栈顶出现可归约的句柄就弹栈归约。

二义性:若文法的某个句子存在**两棵不同的语法树**,该文法就是**二义**的,编译器无法确定唯一的语义,**必须消除**。

```text
文法 E → E + E | E * E | id 是二义文法
句子 id + id * id 有两棵语法树:
树 1: 先算加法, 把乘法挂在加法的右子树下
树 2: 先算乘法, 符合日常优先级习惯
消除办法: 引入 T、F 等层次重写文法, 或附加优先级与结合性规则
```

用移进-归约法分析 id + id * id 的过程如下,文法仍用上文 E、T、F 那一组表达式产生式:

```text
1. 移进 id, 归约为 F, 再归约为 T, 再归约为 E
2. 移进 +
3. 移进 id, 归约为 F, 再归约为 T
4. 移进 *
5. 移进 id, 归约为 F, 此时栈顶是 T * F, 归约为 T
6. 此时栈顶是 E + T, 归约为 E, 分析成功
```

常考对照:**自上而下要消除左递归,自下而上不存在这个问题**;LR 分析器由**总控程序、分析表和分析栈**组成,是**应用最广的自下而上方法**,能识别绝大多数程序设计语言的结构。

## 表达式与逆波兰式

**中缀表达式**是日常写法,运算符在两个操作数中间;**后缀表达式(逆波兰式)**把运算符放在操作数之后;**前缀表达式(波兰式)**把运算符放在操作数之前。**后缀表达式不需要括号**,最适合计算机**用栈求值**。

中缀转后缀的手工方法:按运算优先级给中缀式**补齐括号**,把每对括号内的运算符**移到对应右括号的位置**,最后**去掉全部括号**。

```text
例 1: a + b * c
补齐括号: (a + (b * c))
运算符后移并去括号: a b c * +

例 2: (a + b) * (c - d)
后缀表达式: a b + c d - *
前缀表达式: * + a b - c d

例 3: a - b - c (同级运算符左结合, 先算左边)
补齐括号: ((a - b) - c)
后缀表达式: a b - c -
```

后缀表达式求值用栈:从左到右扫描,**遇到操作数就入栈**;遇到运算符就**弹出栈顶两个数**运算,**先弹出的是右操作数**,结果压回栈;扫描结束,**栈顶就是答案**。

```text
例题: 求后缀表达式 3 4 + 5 *
扫描 3: 栈 [3]
扫描 4: 栈 [3, 4]
扫描 +: 弹出 4 和 3, 算 3 + 4 = 7, 栈 [7]
扫描 5: 栈 [7, 5]
扫描 *: 弹出 5 和 7, 算 7 * 5 = 35, 栈 [35]
结果 35, 对应中缀表达式 (3 + 4) * 5
```

再练一道带减法和除法的,体会操作数顺序:

```text
例题: 求后缀表达式 8 5 3 - /
扫描 8: 栈 [8]
扫描 5: 栈 [8, 5]
扫描 3: 栈 [8, 5, 3]
扫描 -: 弹出 3 和 5, 先弹出的是右操作数, 算 5 - 3 = 2, 栈 [8, 2]
扫描 /: 弹出 2 和 8, 算 8 ÷ 2 = 4, 栈 [4]
结果 4, 对应中缀表达式 8 / (5 - 3)
```

> 考点提示:上午题常给中缀让选后缀,或给后缀让求值。转换用**加括号法**不容易错;求值注意减法和除法的操作数顺序——**先弹出的是右操作数**,5 3 - 的结果是 **2 而不是 -2**,这里最容易翻车。

## 传值调用与传引用调用

**形参**是函数定义时的参数,**实参**是调用时传入的参数。**传值调用**(call by value):把实参的值复制一份给形参,**函数内对形参的任何修改都不影响实参**。**传引用调用**(call by reference):形参是实参的**别名**,**函数内改形参就是改实参本身**。**C 语言本身只有传值**,但传指针可以达到传引用的效果。

```c
void swap1(int x, int y) {        // 传值调用
    int t = x; x = y; y = t;
}
void swap2(int *x, int *y) {      // 传指针, 效果等同传引用
    int t = *x; *x = *y; *y = t;
}
int main(void) {
    int a = 3, b = 5;
    swap1(a, b);
    printf("%d %d\n", a, b);      // 输出 3 5, 交换失败
    swap2(&a, &b);
    printf("%d %d\n", a, b);      // 输出 5 3, 交换成功
    return 0;
}
```

再看一道经典考题,一个函数里两种调用方式混用:

```c
void f(int x, int *y) {
    x = x + 1;
    *y = *y + 1;
}
int main(void) {
    int a = 1, b = 1;
    f(a, &b);
    printf("%d %d\n", a, b);      // 输出 1 2
    return 0;
}
```

**x 是传值**,加 1 只改了副本,a 仍为 1;y **传的是 b 的地址**,*y 指向 b 本体,b 被改成 2。

两个常见变形:C 语言里**数组作为参数传的是首地址**,**效果等同传引用**,函数内修改数组元素会影响实参;**Java 只有传值这一种方式**,对象的引用本身也是按值复制的,所以 Java 里想交换两个对象引用的函数同样无效。

类比前端:JS 的函数参数行为与此完全一致——基本类型按值传(函数里改形参不影响外面),对象传的是引用的副本(改对象属性会影响原对象,但给形参重新赋值不影响外面)。swap 这道题放到 JS 里就是:传两个 number 永远换不掉,包成对象传进去改属性就能换掉,道理一模一样。

> 考点提示:**阅读程序写输出**的题几乎年年考。解题要诀:逐个形参判断是**传值还是传地址**,**传值的修改全部作废,传地址的修改写回实参**。C 语言里看到 & 取地址和 * 解引用就要打起精神,多半是考点所在。

## 类型系统

类型系统从两个维度交叉分类。按检查时机分:**静态类型**在编译期就确定并检查变量类型,代表是 Java、C、C++;**动态类型**在运行期才确定类型,代表是 Python、JavaScript。按转换严格程度分:**强类型**不允许危险的隐式类型转换,代表是 Java、Python;**弱类型**会做大量隐式转换,代表是 JavaScript,C 的隐式转换也偏多。

```text
常见语言归类:
Java:       静态 + 强类型
Python:     动态 + 强类型  (类型运行期才定, 但 "1" + 1 直接报错)
JavaScript: 动态 + 弱类型  (类型运行期才定, "1" + 1 得到 "11")
C:          静态类型, 隐式转换多, 通常归为偏弱
```

注意一个反直觉组合:**Python 是动态强类型**——变量类型运行期才确定,但确定之后不会悄悄转换,字符串加数字直接抛 TypeError,这一点和 JS 完全相反。

记忆口诀:**静态动态看检查时机,强弱看转换是否自由**。判断时先问类型什么时候定,再问能不能悄悄转换。考试常把 Python 和 JS 放在一起对比,两者都是**动态类型**,**区别全在强弱上**。

## 作用域

**静态作用域(词法作用域)**:变量的可见性由**程序正文的书写位置**决定,编译期就能确定,绝大多数语言(Java、C、JS、Python)都是静态作用域。**动态作用域**:变量的可见性由**运行时的调用链**决定,函数里访问自由变量时沿调用栈向上找,早期 Lisp、Bash 属于此类。

```text
示例程序 (伪代码):
int x = 1
void g() { print(x) }
void f() { int x = 2; g() }
main 中调用 f()

静态作用域: g 里的 x 看 g 定义处的环境, 输出全局的 1
动态作用域: g 里的 x 看调用链, f 调用了 g, 输出 f 里的 2
```

类比前端:JS 是静态作用域,闭包记住的是定义位置——这就是面试常考的"函数在哪里定义,作用域链就沿哪里找"。而 JS 的 this 恰好是动态语义:不看定义在哪,只看谁调用了它,这正是动态作用域的行为模式,可以借 this 体会两种作用域的本质差别。

```javascript
var x = 1;
function g() { console.log(x); }
function f() { var x = 2; g(); }
f();   // 输出 1 而不是 2: JS 是静态作用域, g 拿到的是全局的 x
```

> 考点提示:给一段嵌套函数程序问输出,先确认语言是**静态作用域**(软考默认都是),**沿定义位置向外层找变量**;只有题目明确说明动态作用域才沿调用链找。静态与动态类型的归类表也常考,记住 **Python 是动态强类型**这个反直觉组合。

## 写在最后

程序设计语言这一章性价比极高:**编译六阶段、传参方式、逆波兰式、有限自动机**四块覆盖了大部分分值,而且全是套路题。建议把**后缀表达式求值、自动机判串、传值传引用**这三类计算各练五道,再把编译各阶段的错误归类记牢,考场上这些分就是默写。

## 例题精练

> 说明:本节例题按官方教材考点与历年真题风格编写,用于自测与查漏补缺,**非原书题目**。建议先遮住解析独立作答,再对答案。

### 例题 1(编译阶段错误归类)

编译过程中,"表达式缺少右括号"这一错误在( )阶段被发现。

A. 词法分析  B. 语法分析  C. 语义分析  D. 目标代码生成

> 答案:**B**。解析:词法分析只负责**把字符流切成单词**,不认识括号配对;**括号是否匹配、语句结构是否合法**是语法分析按文法规则检查的内容;语义分析管**类型匹配、变量是否声明**这类含义问题。记法:**词法认词、语法认结构、语义认含义**。

### 例题 2(逆波兰式)

表达式 a+b*(c-d) 的后缀式(逆波兰式)为( )。

A. abcd-*+  B. ab+cd-*  C. abc-d*+  D. +a*b-cd

> 答案:**A**。解析:先算括号 c-d → cd-;再与 b 相乘 → bcd-*;最后与 a 相加 → abcd-*+。技巧:**运算符紧跟在它的两个操作数后面**,优先级高的先出现;D 是前缀式,放进来当干扰项。

### 例题 3(传值与传引用)

```
procedure f(a, b)        // a 为传值调用, b 为传引用调用
    a = a + 1
    b = b + a
主程序: x = 1; y = 2; 调用 f(x, y) 后输出 x 和 y
```

A. 1 和 4  B. 2 和 4  C. 1 和 3  D. 2 和 3

> 答案:**A**。解析:a 是 x 的**副本**,a 变 2 但 x 不变,仍为 1;b 直接绑定 y,b = 2 + 2 = 4 写回 y。**传值改副本、传引用改本尊**,这是软考几乎每年都送的分。

### 例题 4(正规式)

正规式 (a|b)*abb 表示的语言是( )。

A. 所有以 abb 结尾的 a、b 串  B. 所有以 abb 开头的 a、b 串  C. 所有含 abb 的 a、b 串  D. 仅 abb 本身

> 答案:**A**。解析:(a|b)* 表示**任意长度的 a、b 串**(含空串),其后必须紧跟 abb,所以整体是"以 abb 结尾"。真题常反过来问:给语言描述选正规式,同样抓"任意前缀用 (a|b)*"这个结构。
